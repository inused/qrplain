# QRPlain 技术设计

QRPlain 是本地离线二维码生成与解析工具，提供浏览器界面和 CLI。正文、图片和页面资源均由本机程序处理。

程序使用 Go 1.20.7，构建目标为 Windows、Linux、macOS 的 amd64 和 arm64。Windows 7 的兼容目标为 amd64，Linux 重点验证环境为银河麒麟 V10。各平台的验证状态见 [验证记录](VALIDATION.md)。

## 运行结构

| 位置 | 职责 |
| --- | --- |
| `main.go` | 分派界面、CLI、帮助和版本命令 |
| `internal/qr/` | UTF-8 文件读取、二维码编解码和 PNG 保存 |
| `internal/cli/` | 参数解析、终端显示和退出码 |
| `internal/webui/` | 本机 HTTP 服务、浏览器启动和内嵌页面 |
| `scripts/` | 六平台编译和浏览器端到端验证 |
| `README.md` | 使用与构建说明 |
| `docs/VALIDATION.md` | 验证结果与运行环境 |
| `docs/THIRD_PARTY.md` | 第三方许可与专利授权原文 |
| `LICENSE` | 项目 MIT 许可证 |

浏览器界面和 CLI 调用同一套编解码逻辑。CLI 直接执行子命令，界面模式启动 HTTP 服务。

生成器对数字、字母数字和字节内容做混合分段编码，减少混合正文占用的位数。识别器先定位二维码；定位失败时，使用纯码模式识别无透视变形的二维码，并执行结构与纠错校验。

HTTP、文件读写、图片格式处理和静态资源内嵌使用 Go 标准库。页面使用 HTML、CSS 和 JavaScript，随可执行文件分发。

## 命令与输入

```text
qrplain
qrplain ui
qrplain encode --text "正文"
qrplain encode --file content.txt
qrplain encode --file content.txt --out qr.png --size 1024 --level M
qrplain decode --image qr.png
qrplain --help
qrplain --version
```

无参数运行打开浏览器界面。`encode` 接受 `--text` 或 `--file`，二者互斥，缺值或空值时报错。正文恰好是已知选项名时使用等号传值，例如 `--text=--out`。

文本文件使用 UTF-8，去除开头 BOM，保留其余空白、CRLF 和末尾换行。编码器根据正文、编码模式和纠错等级判断容量，超限返回错误。

`encode` 默认输出终端二维码；指定 `--out` 时保存 PNG。输出路径须为新文件，父目录须存在。写入或关闭文件失败时清理未完成的文件，并报告错误。

`decode` 读取 PNG/JPEG，向标准输出写入正文，再补一个结果结束换行。错误和提示写入标准错误。退出码为 0 表示成功，1 表示处理或输出失败，2 表示参数错误。

## 图片与容量

PNG 默认边长为 512 像素，最大为 4096 像素，默认纠错等级为 M，可选择 L、M、Q、H。绘制时每个模块占相同的整数像素，四周保留标准留白，剩余像素填白。尺寸不足以容纳模块和留白时返回错误。

输入图片的文件大小上限为 16 MiB，像素数上限为 16,777,216。程序先检查图片头中的尺寸，再展开图片；透明背景合成白底后识别。

普通二维码最大为 Version 40，码区为 177×177 模块。以下是单一编码模式的最大容量：

| 模式 | L | M | Q | H |
| --- | ---: | ---: | ---: | ---: |
| 数字 | 7089 位 | 5596 位 | 3993 位 | 3057 位 |
| 标准字母数字字符集 | 4296 字符 | 3391 字符 | 2420 字符 | 1852 字符 |
| 字节 | 2953 字节 | 2331 字节 | 1663 字节 | 1273 字节 |

标准字母数字字符集包含数字、大写英文字母及部分符号。常见汉字通常占 3 个 UTF-8 字节；混合正文和字符集声明会影响实际容量。

密集二维码需要更大的图片。Version 40 加上四周各 4 模块留白，按每模块 4 像素计算需要 740 像素，保存时可选 768 或 1024 像素。

## 终端显示

默认的 `half` 模式用 Unicode 半块字符在一个字符格中表示上下两个模块。`full` 模式每个模块占两列。两种模式都设置黑白颜色并保留留白；旧 Windows 控制台的全块模式使用 Win32 颜色 API。

程序按当前终端或窗格的列数检查宽度，留一列防止最右列自动换行。最大版本半块模式需要至少 186 列，全块模式需要至少 371 列。宽度不足时提示调宽窗口或保存 PNG。

读取终端尺寸失败时，程序提示后完整输出。重定向的内容包含 ANSI 控制序列。调整窗口后需重新执行命令；手机扫码时需让整个二维码同时可见。

## 浏览器界面

界面使用一个文本区域和一个图片预览区域，提供生成、打开图片识别、保存 PNG 和退出按钮。修改正文、尺寸或纠错等级后，已有生成结果失效，重新生成后才能保存。

浏览器文本框会将 CRLF 规范为 LF。程序另存识别结果的原文，未编辑就重新生成时使用原文；用户编辑后使用文本框内容。

本机服务监听 `127.0.0.1` 的随机端口。每次启动生成访问凭据，放在页面 URL 的片段中；修改状态的请求同时校验 Host、Origin 和凭据。图片通过浏览器上传，API 接收图片数据。

图片处理串行执行，同时提交的其他任务返回忙碌提示。上传长度和图片尺寸均受限制，识别结果以文本显示。

系统默认浏览器由平台 URL 启动器打开，失败时显示访问地址。页面的“退出程序”按钮或终端 Ctrl+C 结束服务，关闭标签页保留进程。Windows 使用控制台程序，双击时可能显示控制台窗口。

## 构建与分发

`scripts/build.sh` 和 `scripts/build.bat` 使用 `CGO_ENABLED=0`、`-trimpath` 和 `-ldflags "-s -w"` 构建六个平台组合，输出到 `dist/`，任一目标失败即停止。BAT 按脚本位置定位项目根目录，并在退出时恢复工作目录和环境变量。

编译脚本将 `LICENSE` 和 `docs/THIRD_PARTY.md` 复制到 `dist/` 的对应位置，随可执行文件分发。

原创代码采用 MIT。第三方组件遵循各自的 MIT、BSD-3-Clause 和 Apache-2.0 条款；许可及附加专利授权原文见 [第三方许可说明](THIRD_PARTY.md)。

## 验证

自动化检查覆盖容量边界、混合正文、原文回读、图片尺寸和格式、文件输入输出、CLI 参数、终端模块布局、本机访问控制和页面交互。

Go 检查使用 `go test ./...`、`go test -race ./...` 和 `go vet ./...`。浏览器端到端测试使用已有 Chromium 与 Node.js 的 CDP 接口。实机、浏览器和扫码器的验证范围记录在 [验证记录](VALIDATION.md)。
